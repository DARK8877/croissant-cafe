# Круасан и точка — учебный сайт кофейни

HTML, CSS и JavaScript на сайте + маленький сервер на Node.js (без библиотек), который сохраняет заказы и бронирования **в файлы**.

## Где что хранится

| Данные | Где | Видно на других устройствах |
|---|---|---|
| Заказы | Google Таблица (GitHub Pages) или `data/orders.json` (локальный `server.js`) | да |
| Бронирования | Google Таблица или `data/bookings.json` | да |
| Каталог товаров, настройки сайта, фото | Google Таблица (лист `Site`) или `data/site.json`; в браузере — кэш | да, обновляется за 5–15 секунд |
| Корзина | `localStorage` браузера | нет (так и должно быть) |

Заказы может читать и менять статус **только администратор** — сервер проверяет логин и пароль и выдаёт токен. Посетитель может только создать заказ.

## Аккаунты и админка

- На сайте есть кнопка **«Войти»** в шапке: вход и простая регистрация (логин, пароль от 6 символов, имя, телефон). После входа имя и телефон подставляются в заказ, а заказ привязывается к аккаунту.
- Пользователи хранятся в листе `Users` Google Таблицы (или в `data/users.json`). Пароли в виде хэша с индивидуальной солью, сами пароли нигде не сохраняются. **Лист `Users` нельзя открывать для общего доступа.**
- **Администратор**: логин `ADMIN`, пароль задаётся в «Свойствах скрипта» (`ADMIN_PASSWORD`), а не в коде. Войдите через ту же кнопку «Войти»: в окне аккаунта появится кнопка «Открыть админку». У обычных пользователей и гостей этой кнопки нет, а ссылок на админку на сайте нигде нет. Сам сервер всё равно проверяет роль, поэтому открыть админку по прямой ссылке без входа администратора нельзя.
- После 5 неверных паролей подряд вход для этого логина блокируется на 15 минут.
- Токены действуют 6 часов, потом нужно войти заново.

## Доставка

Доставка **только по Таразу**: в форме заказа город зафиксирован («Тараз»), адрес обязателен, а сервер отклоняет любые заказы с другим городом. Проверить, что улица действительно в Таразе, сервер не может: это должен подтвердить оператор по телефону.

## Структура файлов

| Файл | Назначение |
|---|---|
| `config.js` | Адрес Google Apps Script (для GitHub Pages) |
| `apps-script/Code.gs` | Код для Google Apps Script: принимает заказы, пишет в Google Таблицу |
| `server.js` | Локальный сервер: раздаёт сайт, принимает заказы/брони, пишет в `data/` |
| `data/` | Файлы `orders.json` и `bookings.json` (создаются сами при первом заказе) |
| `index.html`, `style.css`, `script.js` | Сайт, каталог, корзина, формы |
| `storage.js` | Общая логика: каталог/настройки в localStorage + функции обращения к серверу (API) |
| `login.html/.css/.js` | Запасная страница входа по прямой ссылке (на сайте не показана); основной вход — кнопка «Войти» |
| `admin.html/.css/.js` | Админ-панель |
| `package.json`, `.gitignore` | `npm start` и защита `data/` от попадания в GitHub |

## Запуск

Нужен Node.js (nodejs.org, версия 18 и новее). Устанавливать пакеты не нужно.

1. Откройте папку проекта в VS Code, терминал: `Terminal → New Terminal`.
2. Выполните `node server.js` (или `npm start`).
3. Откройте **http://localhost:3000** — сайт, **http://localhost:3000/login.html** — админка.
4. Для учебного запуска: логин `ADMIN`, пароль `demo123`. Вход через кнопку «Войти» на главной странице.

Своё значение пароля (для настоящего сайта обязательно):

- Windows (PowerShell): `$env:ADMIN_PASSWORD="мой-длинный-пароль"; node server.js`
- macOS/Linux: `ADMIN_PASSWORD="мой-длинный-пароль" node server.js`

**Live Server** тоже можно использовать для внешнего вида сайта: страница сама обращается к серверу на порту 3000. Но сервер `node server.js` при этом должен быть запущен. Если он не запущен, форма заказа покажет понятную ошибку, а корзина не очистится: заказ **не** потеряется молча.

Заказы можно открыть и без админки: файл `data/orders.json` — обычный текстовый файл.

## Заказы на GitHub Pages (бесплатно, через Google Таблицу)

GitHub Pages раздаёт только готовые файлы и не запускает Node.js, поэтому `server.js` там работать не будет. Вместо него используется **Google Apps Script**: заказы и бронирования попадают в вашу Google Таблицу (это и есть отдельный файл), а читать их через админку может только тот, кто знает пароль.

**Настройка (один раз, ~10 минут):**

1. Откройте sheets.google.com → создайте пустую таблицу, назовите её «Кофейня».
2. В таблице: **Расширения → Apps Script**. Удалите всё в редакторе и вставьте содержимое файла `apps-script/Code.gs`. Сохраните.
3. Слева **Настройки проекта (шестерёнка) → Свойства скрипта → Добавить свойство**: имя `ADMIN_PASSWORD`, значение — ваш длинный пароль (не `demo123`). По желанию добавьте `ADMIN_LOGIN` (по умолчанию `ADMIN`).
4. Вверху **Начать развёртывание → Новое развёртывание → тип «Веб-приложение»**. Выполнять от имени: **Я**. Доступ: **Все**. Нажмите «Развернуть» и разрешите доступ (Google предупредит, что приложение не проверено: «Дополнительно → Перейти»). Это нормально для своего скрипта.
5. Скопируйте **URL веб-приложения** (оканчивается на `/exec`) и вставьте в `config.js`:
   `window.APPS_SCRIPT_URL = "https://script.google.com/macros/s/.../exec";`
6. Загрузите проект на GitHub (шаги ниже). Листы `Orders` и `Bookings` создадутся сами при первом заказе.

**Если вы обновили `Code.gs` до этой версии** (аккаунты, адрес доставки), обязательно переразверните скрипт, иначе сайт будет получать старые ответы. В новой версии появятся листы `Users`, а в `Orders` добавятся столбцы `city`, `address`, `userLogin`: **Развернуть → Управление развёртываниями → ✏️ → Версия: новая → Развернуть** (адрес остаётся прежним).

**Публикация на GitHub Pages:**

1. github.com → **New repository** (имя, например, `croissant-cafe`, Public) → **Create**.
2. **Add file → Upload files**, перетащите файлы проекта (`index.html` в корне). Папку `data/` и `server.js` можно не загружать: на Pages они не нужны. Папку `apps-script/` загружать можно: в ней нет паролей.
3. **Settings → Pages → Build and deployment → Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты появится ссылка `https://ваш-логин.github.io/croissant-cafe/`.
5. Проверьте: картинки, навигацию, оформите тестовый заказ, откройте `login.html` и войдите: заказ должен появиться в таблице и в админке.

**Что важно:**

- URL веб-приложения виден всем, кто откроет код сайта. Это нормально: заказ может создать любой посетитель, а читать заказы без пароля нельзя. Пароль в код не пишите, он хранится только в «Свойствах скрипта».
- Таблицу не делайте общедоступной: в ней имена и телефоны клиентов.
- У Apps Script есть суточные квоты и небольшая задержка ответа (1–3 секунды). Для учебного сайта этого хватает.
- Это не промышленное решение: для настоящего магазина нужна база данных (см. ниже).

## Локальный запуск с `server.js` (альтернатива)

Если `config.js` пустой, сайт использует `server.js` и файлы `data/orders.json`, `data/bookings.json` (см. раздел «Запуск»). Это удобно для разработки. Для настоящего сервера на хостинге с Node.js задайте `ADMIN_PASSWORD` и используйте HTTPS.

## Что ещё нужно знать

- **Изменения «почти в реальном времени».** Это опрос сервера, а не постоянное соединение: сайт проверяет версию каталога каждые 15 секунд, админка обновляет заказы и брони каждые 10 секунд (и сразу при возврате на вкладку). Для мгновенных обновлений нужны WebSocket или Supabase Realtime / Firebase.
- **Каталог общий для всех устройств.** Пока админ ни разу не сохранил изменения, на сайте показывается демо-каталог. Первое сохранение в админке (любое) публикует каталог на сервере.
- **Цены проверяет сервер.** Как только каталог сохранён на сервере, при оформлении заказа цена и название берутся из него, а не из браузера; недоступный товар заказать нельзя.
- Если два администратора правят одновременно, побеждает последнее сохранение (перед каждым сохранением админка подтягивает свежую версию, поэтому чужие правки обычно не затираются).
- Фото хранятся в каталоге (сжатые до 480 px). Для десятков товаров с собственными фото лучше внешнее хранилище; Apps Script ограничен размером ~4 МБ на весь каталог.
- Квоты Apps Script: каждый открытый сайт делает лёгкий запрос раз в 15 секунд, админка — раз в 10. Для небольшой кофейни этого хватает; при большом потоке посетителей лучше `server.js` на хостинге или Supabase.
- Токены админа временные (в памяти сервера / на 6 часов в Apps Script): потом нужно войти заново.
- Кнопка «Восстановить демонстрационный каталог» заменяет каталог и тексты на сервере (у всех посетителей), но **не удаляет заказы и брони**.
- Учебный сервер хранит данные в JSON-файлах и подходит для небольшого количества заказов. Для нескольких параллельных серверов или большого потока нужна база данных.

## Переход на базу данных (Supabase)

1. Создайте проект на supabase.com и таблицы `products`, `site_settings`, `orders`, `bookings`.
2. Включите **Row Level Security** и политики: все могут читать `products` и `site_settings`; посетители могут только создавать (`INSERT`) в `orders` и `bookings`; читать и менять статусы может только вошедший администратор (Supabase Auth).
3. Фото переведите в Supabase Storage.
4. В `storage.js` замените функции `createOrder`, `fetchOrders` и остальные на запросы к Supabase. На сайте используйте только публичный `anon`-ключ, ключ `service_role` никогда не размещайте на сайте.
